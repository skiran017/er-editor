# Documentation Site Design

**Date:** 2026-04-27
**Status:** Spec — ready for plan
**Related:** [docs/superpowers/specs/2026-04-22-target-architecture-design.md](./2026-04-22-target-architecture-design.md) (v2 architecture)

---

## 1. Goal

Replace the current ad-hoc collection of root-level Markdown files with a published documentation site that has two distinct surfaces:

- **User docs** — high-level. Help students and instructors use the editor (build a diagram, save/export, embed in Moodle).
- **Dev docs** — detailed. Help future contributors understand and extend the v2 codebase (architecture, concepts, recipes, API reference).

The site must stay accurate as the code evolves: API reference and key code snippets must be generated from source, not hand-copied.

## 2. Architecture

**Static-site generator:** VitePress (Vue-based, Markdown-first, fast).
**API reference:** TypeDoc with `typedoc-plugin-markdown` + `typedoc-vitepress-theme`. Reads public barrel files (`src/domain/index.ts`, `src/state/index.ts`, `src/notation/index.ts`) and emits Markdown into `docs/api/` at build time. Output is **gitignored** — regenerated on every build, never committed.
**Code snippets in prose:** VitePress's `<<< @/path/to/file.ts#region` include syntax. Snippets reference *named regions* in source (`// #region foo` … `// #endregion`) so refactors that move code don't break includes.
**Keybindings cheatsheet:** generated at build time by `scripts/gen-keybindings-table.ts`, which imports `src/interaction/keybindings.ts` and emits a Markdown table partial. Keeps the user-facing shortcut reference in sync with the source-of-truth keybinding registry.
**Localization:** English only for v1 of the docs site. VitePress supports i18n natively if added later.
**Deployment:** deferred. The site builds locally (`pnpm docs:build`); a hosting target will be chosen separately.

## 4. Content plan

### 4.1 Landing (`docs/index.md`)

Single-screen introduction: project name, one-paragraph pitch, hero screenshot, two prominent buttons (User Docs / Dev Docs), tech-stack footer line.

### 4.2 User docs

Each page is sized to its job — short tour pages 100-300 words, deep task pages 600-1200 words. Each task page includes annotated screenshots.

| Page | Contents |
|---|---|
| `user/index.md` | What ER Editor is, who it's for, what it isn't. 1 paragraph + screenshot. |
| `user/quick-start.md` | "Make your first ER diagram in 3 minutes." Annotated screenshots: pick Entity → click → name it → pick Relationship → connect. Closes with "open the menu to save." |
| `user/tools.md` | Toolbar tour. One row per tool with icon + what it does + how to invoke (click vs drag). Includes pen/touch notes (long-press for rubberband, two-finger pan/pinch). |

| `user/tasks/cardinality.md` | 1:1 vs 1:N vs N:N, partial vs total participation, with diagrams. Quick-relationship tools (1:1, 1:N, N:N) shown as shortcuts. |

### 4.4 Auto-generated content

- **API Reference (`docs/api/`)** — TypeDoc reads the three barrels in §3, emits Markdown grouped by source module. Linked from the top nav. Regenerated on `pnpm docs:dev` / `pnpm docs:build`.
- **Keybindings table (`docs/user/_keybindings-table.md`)** — `scripts/gen-keybindings-table.ts` imports `src/interaction/keybindings.ts` and writes a Markdown table partial. Included via `<!--@include: ./_keybindings-table.md-->` from `user/shortcuts.md`. Regenerated on `pnpm docs:dev` / `pnpm docs:build`.

### 4.5 Authoring conventions

- **Snippets reference named regions, not line numbers.** Every page that includes source uses `<<< @/src/path/file.ts#region-name`. Region markers in source code use `// #region region-name` … `// #endregion`. Region names describe the *concept* (`pick-tool-event`, `diagram-type`) so they survive refactors that move the code.
- **Recipes use diff-style code blocks** (`+` and `-` lines) showing exactly which lines to add to which file. Narrative-only recipes that say "add a property to the type" without showing where always rot.
- **Screenshots live in `docs/public/screenshots/`** with stable filenames (`tools-toolbar.png`, `quick-start-step-1.png`). Re-take on visual changes; commit to git so the docs build is offline-buildable.

## 5. Build pipeline

### 5.1 `package.json` scripts

```json
{
  "scripts": {
    "docs:api": "typedoc --options docs/.vitepress/typedoc.json",
    "docs:keybindings": "tsx scripts/gen-keybindings-table.ts",
    "docs:dev": "pnpm docs:keybindings && pnpm docs:api && vitepress dev docs",
    "docs:build": "pnpm docs:keybindings && pnpm docs:api && vitepress build docs",
    "docs:preview": "vitepress preview docs"
  }
}
```

`docs:keybindings` and `docs:api` are chained before both `docs:dev` and `docs:build` so the generated content is always fresh.

### 5.2 TypeDoc config (`docs/.vitepress/typedoc.json`)

```json
{
  "entryPoints": [
    "src/domain/index.ts",
    "src/state/index.ts",
    "src/notation/index.ts"
  ],
  "out": "docs/api",
  "plugin": ["typedoc-plugin-markdown", "typedoc-vitepress-theme"],
  "readme": "none",
  "githubPages": false,
  "excludeInternal": true,
  "excludePrivate": true,
  "sort": ["alphabetical"]
}
```

Restricting entry points to public barrels prevents internal helpers leaking into the API reference. Anything not re-exported from the three barrels stays hidden.

### 5.3 Keybindings generator (`scripts/gen-keybindings-table.ts`)

Imports `keybindings` from `src/interaction/keybindings.ts`, groups by `category`, formats a Markdown table per category with columns `Action | Keys | When`, writes to `docs/user/_keybindings-table.md`. Plain Node script, run via `tsx`. No tests — failure is loud (script exits non-zero, build fails).

### 5.4 VitePress config (`docs/.vitepress/config.ts`)

Top nav: User Docs, Dev Docs, API Reference, Changelog.
Footer: GitHub repo link.
Sidebars: defined per section (user, dev, api).
**Excluded from build/nav:** `docs/superpowers/**`, `docs/archive/**` (`srcExclude` setting). Files remain on disk and reachable by direct URL but invisible to navigation.

## 7. Out of scope / deferred

- **Deployment.** No hosting target chosen. Site builds locally; deploy story is a follow-up. `dev/build-deploy.md` carries a placeholder until then.
- **i18n.** English only. VitePress's locale support can be added later without restructuring.
- **Drift CI check.** Considered but rejected — high false-positive rate on refactors, low value at this project's scale. TypeDoc + region-marker snippets cover most drift risk.
- **Search.** VitePress ships local search by default; sufficient for now. Algolia DocSearch can be added if hosted.
- **In-app help / contextual links.** The existing in-app Cheatsheet modal stays as-is — the docs site is the canonical reference. A "Help" link from the menu pointing to the docs site can be added later.

## 8. Acceptance criteria

The work is done when:

- `pnpm docs:dev` opens a working local site at `localhost:5173` (or VitePress default port).
- `pnpm docs:build` produces a static `docs/.vitepress/dist/` with no errors.
- Every page listed in §4.2 and §4.3 exists with real content (not "TODO").
- The API reference under `/api/` covers every public symbol from `domain/`, `state/`, `notation/`.
- The keybindings table on `/user/shortcuts/` matches `src/interaction/keybindings.ts`.
- All migrations in §6 are complete: archive files moved, originals deleted from root where appropriate.
- `pnpm typecheck && pnpm lint && pnpm test --run` still pass (no regressions in the source tree from doc edits).
